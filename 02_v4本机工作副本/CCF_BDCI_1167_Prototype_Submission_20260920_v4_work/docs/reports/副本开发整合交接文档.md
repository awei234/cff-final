## 2. 本次完成内容

### 2.1 `jit-constrained` 正式接入 UCR runner

`run_experiment.py --all` 现在运行四臂 × 三 seed：

| 实验臂 | 含义 |
|---|---|
| `no-rail` | baseline，保留旧名称以兼容历史数据 |
| `prompt-only` | 仅提示词约束 |
| `full-rail` | 固定硬 Rail |
| `jit-constrained` | JIT 选择安全 Profile，同时保持硬 Rail、工具白名单和预算 |

JIT 臂通过相对路径调用 `competition_runner/competition_runner/harness/` 中已有的 Planner、Selector、Validator 与 Archive，不复制第二套策略实现。

调用方传入的重试参数不能扩大 JIT 预算；runner 在任何模型调用发生前，将最大调用次数同时截断到 `max_provider_calls` 和 `max_retries + 1`。

每个 JIT 运行新增保存：

- `harness_manifest.json`；
- `harness_validation.json`；
- `runtime_metrics.json`；
- `harness/harness_archive.json`；
- Manifest、验证、成本、时延、证据和档案的 SHA-256 Provenance。

### 2.2 四臂聚合与兼容性

聚合器在检测到完整 `jit-constrained` 三 seed 数据时自动输出四臂比较；对于冻结 S3 等历史三臂数据仍保持兼容。

冻结 S3 没有直接增加第四臂，因为修改它会破坏任务哈希、Manifest 哈希和协议身份。新的四臂结果作为独立、不可覆盖的数据集保存。

### 2.3 四臂交付验证器

新增 `verify_jit_comparison.py`，离线验证：

- 4 个实验臂 × seed 42、43、44 共 12 个运行；
- 运行身份、必需文件和聚合完整性；
- Provenance 文件哈希；
- JIT Manifest Schema/白名单/预算；
- JIT Rail 必须启用；
- 成本、时延和调用次数；
- Harness archive 自哈希；
- `results.json` 证据哈希；
- 篡改后的档案必须被拒绝。
