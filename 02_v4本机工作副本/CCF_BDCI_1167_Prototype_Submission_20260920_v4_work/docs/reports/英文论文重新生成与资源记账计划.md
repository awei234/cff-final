## 2. 关键对齐：「咱们系统的流程」实际是两条链

必须先说清楚，否则容易做错方向：

### 流程 A —— 科研矩阵流水线（可审计素材与证据）
`run_research_matrix.py` → 每主题产出：
`research_materials.json`、`plan.json`、`review.json`、`experiment_*`、`claim_ledger.json`、
`tool_trace.jsonl`、`rail_events.jsonl`、`execution_report.json`、`provenance.json`、`paper.tex`；
顶层产出 `matrix_execution_report.json`、`matrix_verification_report.json`、统一 `paper.tex`。
- 特点：**真实调用** DeepSeek（plan/review/report 三阶段），真实检索 OpenAlex/arXiv/Crossref，真实跑 UCR 本地基准；
- 标签：`process_evidence_only`，来源默认 `citation_allowed=false`，最终状态只能是 `completed_pending_human_review`；
- 产出论文模板为 `ctexart`（中文），**不是** CGA-Agent 风格的英文论文。

### 流程 B —— 论文生产/修订链（论文文件本身）
`paper/generation/` 下的：`apply_revisions.py`（修订）、`export_pdf.py`（Word COM 导出 PDF）、
`tighten_layout.py`（版面压到 ≤15 页）、`refresh_checksums.py`（刷新校验），
再同步 `submission_manifest.json` / `CHECKSUMS.sha256` / `resource_report.md`。
- 规则见 `docs/论文修改后同步更新注意事项.md`。

> **本计划 = 先用流程 A 真实产出可审计素材与证据，再用流程 B 产出 15 页英文论文，最后重写资源报告。**
> 因为「同题目、同主旨」的 CGA-Agent 论文属于英文论文，流程 A 的中文 `ctexart` 产物不能直接当交付论文，
> 需要作为**证据与素材**，再据此产出英文论文。

3. 新运行输出目录使用**全新名字**（不覆盖任何历史目录）。

### Phase 1 — 真实跑系统流水线
执行目录：`code/03_技术实现/competition_runner`

**1a. 先离线冒烟（零外部调用，验证环境）**

**1b. 真实运行（产生 DeepSeek 调用）**
```powershell
py -3 run_research_matrix.py --provider deepseek --confirm-live --allow-research-matrix-demo `
  --allow-public-retrieval --max-calls-per-topic 3 --max-total-calls 9 `
  --output-root demo_runs/research_matrix_v5_live
```

预期产物（`demo_runs/research_matrix_v5_live/`）：
- 3 个主题子目录 + 统一 `paper.tex`；

- `matrix_execution_report.json`（`total_provider_calls`）；
- `matrix_verification_report.json`。

失败处理：失败会写 `failure_report.json`，**不会伪造成功论文**；失败需如实记录，不得包装成成功。

### Phase 2 — 产出 15 页英文论文
以 `paper/paper.docx` 为参考（同题目、同主旨、数据可复用），结合 Phase 1 的真实证据产出英文论文：
- 若走 **Word 路线**：直接编辑 `paper/paper.docx` → `paper/generation/export_pdf.py` 导出 `paper/paper.pdf`；
- 若走 **LaTeX 路线**：新建英文 `.tex`（非 `ctexart`）→ 两遍 XeLaTeX 编译；
- 论文中的每个关键数字/结论，必须能追溯到 Phase 1 的 `experiment_results.json` / `claim_ledger.json` / 来源记录。

### Phase 3 — 版面控制到 15 页
- 若超出 15 页，用 `paper/generation/tighten_layout.py` 压缩行距（仅改排版，不改文字/表/图/参考文献）；
- 目标：**恰好 15 页**（评审站点只读前 15 页）。

### Phase 4 — 同步清单与校验
```text

```
按 `docs/论文修改后同步更新注意事项.md` 更新页数、字节数、SHA-256，并核对一致性。

### Phase 5 — 重写 `paper/resource_report.md`（核心要求）
- **清空**旧资源消耗数据：删除第 4 节「生成/编辑过程资源」、第 5 节「历史流水线资源」（含 `demo_runs/research_matrix_live_20260924_authorized` 引用）；
- **只保留本轮**全流程生成论文真实消耗的资源（口径见第 5 节）；
- 保留必要的概述、文件/修订轮次、复现命令、关联文件章节；
- 缺失字段一律 `null` / `not_recorded`，**禁止估算或补造**。

### Phase 6 — 最终校验

并做 Claim–Evidence 一致性、引用验证、结果一致性检查；记录已知残留（如 `paper/paper.tex` 缺失导致第 218 行校验项失败）。

## 6. 风险与边界

1. **概念落差**：流程 A 产出的是中文 `ctexart` 报告，不是 CGA-Agent 英文论文 → 需按 Phase 2 转换，工作量最大。
2. **费用**：真实模式会消耗 DeepSeek 调用（≤9 次），需用户明确确认后执行。
3. **网络**：检索与模型调用依赖外网，任一不可达会写 `failure_report.json`。
4. **不可覆盖**：流水线拒绝写入非空目录；每次运行必须用新目录名。
5. **`paper.tex` 缺失**：`verify_submission.py` 第 218 行要求该文件，本工作副本始终会在该项失败（既有结构性差异）。
6. **合规**：不得新增无证据支持的数据、实验、引用或结论；不得把 `process_evidence_only` 包装成领域科学结论。
7. **敏感信息**：日志与报告中不得出现 API Key / Token / Authorization Header。
