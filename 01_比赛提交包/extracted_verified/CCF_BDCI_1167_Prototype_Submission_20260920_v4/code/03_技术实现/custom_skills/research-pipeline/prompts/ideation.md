# Ideation 选题操作手册

> 从种子领域到新颖、可行的研究想法。改编自 John Schulman《Opinionated Guide to ML Research》、ResearchAgent 方法论、"Can LLMs Generate Novel Research Ideas?"（Si et al.）与标准学术研究实践。
> 本 skill 的执法者：F02（plan 校验）、F04（引用核验）——本阶段产出会作为它们的输入，**引用必须真实**。

## Step 1：探索领域（不许跳过）

### 搜索已有工作（从新到旧）
- 在 arXiv（https://arxiv.org，API 走 https 端口）、**OpenAlex（api.openalex.org，主渠道，无 key 免费）**、Crossref（api.crossref.org）搜索种子领域
- ⚠️ Semantic Scholar（semanticscholar.org）免费层限流严重（2026-08-14 实测 HTTP 429），**默认不用**；确需使用必须串行 + ≥1s 间隔 + 429 退避
- **从最新论文开始**：按日期排序，先读最近的工作，再读奠基性经典
- 推荐搜索顺序：
  1. 近 6 个月 —— 现在正在发生什么？
  2. 近 1-2 年 —— 当前 SOTA 方法是什么？
  3. 奠基论文 —— 经典方法是什么？
- 找这些：
  - 综述论文（总结格局 + 列出开放问题）
  - 高被引新论文（定义当前 SOTA）
  - Workshop 论文（常有早期想法和新兴趋势）

### 建立认知地图
- 这个领域的主要方法有哪些？
- 既定的基准和指标是什么？
- 当前方法的已知局限是什么？
- 哪些问题被视为"开放/未解决"？
- 其他领域的新技术能否用到这里？

### 找缺口
- 读近期论文的 Limitations 和 Future Work 章节
- 找评审中反复出现的抱怨（OpenReview 若有）
- 识别当前方法的假设——能否放宽？
- 找"简单 baseline 仍然表现惊人"的问题（说明社区还没啃下来）

## Step 2：生成候选想法

### 两种路径（选一或结合）

**Goal-driven（推荐）**：从要解决的问题出发。
- "当前 X 方法在 Y 情况下失效，怎么修？"
- "任务 Z 需要太多标注数据，能否用更少的完成？"
- 目标约束搜索范围，贡献清晰。

**Idea-driven**：从技术出发找应用场景。
- "技术 A 在 B 上效果不错，能否用于 C？"
- 风险更高——可能发现想法已存在或不可行。

### 好研究想法的标准
- **新颖**：没人做过（必须验证，Step 3）
- **可行**：在你的资源约束内能实现和测试
- **清晰**：一句话能说清贡献
- **可测**：有具体方法验证是否有效
- **重要**：如果成功，社区会在意

### 坏研究想法的特征
- 太空泛（"改进 NLP"）——需要具体问题和路径
- 太琐碎（"把超参 X 从 0.1 改成 0.01"）
- 不可验证（无法测试）
- 需要你没有的资源（100 块 GPU、专有数据）
- 已存在（没查文献）

## Step 3：验证新颖性（关键，不要跳过）

提交前验证想法没被做过：

### 专门搜索你的想法
- 用你方法的**关键词**搜 OpenAlex 和 arXiv（Semantic Scholar 限流默认不用）
- 搜你**要解决的问题**，不只搜方法名
- 检查你的想法是否是某个更一般已存在方法的特例
- 看你想法最接近论文的 Related Work

### 常见新颖性陷阱
- 你的想法已存在但名字不同（各子领域术语不同）
- 想法被试过但失败了（负结果也要查）
- 想法是已有方法的微小变体
- 最近几个月有人发了相同的并发工作

### 如果想法已存在
- 别立刻放弃。问：能改进它吗？用到新领域？和其他结合？扩大规模？
- 如果确实无改进空间，回到 Step 2

## Step 4：产出（必须全部完成）

### 4.1 `proposal.md` —— 研究提案
- **Introduction**：背景 / 问题陈述 / 关键洞见 / 假设
- **Proposed Approach**：概述 / 方法细节 / 关键创新
- **Related Work**：关键论文 / 与你的差异 / 定位
- **Experiments**：计划实验 / 基准 / 指标 / 预期结果
- **Success Criteria**：什么结果证实/证伪假设
- **References**：完整引用列表（**全部真实可核验**）

### 4.2 `idea.json` —— 结构化总结
```json
{
  "title": "论文标题",
  "description": "1-3 句话：提出什么",
  "motivation": "为什么重要、填什么缺口",
  "proposed_approach": "高层方法 + 为什么有效",
  "related_work": ["真实文献：作者/标题/年份", "与我们的差异"],
  "hypothesis": "可证伪假设",
  "success_criteria": "证实/证伪的判据",
  "topic_mapping": "context | memory | self-evolution"
}
```

### 4.3 `references/` —— 解析的参考文献池
- 每文献一个目录，**目录名 = BibTeX key**
- `meta/meta_info.txt`：title / authors / venue / year / URL
- `meta/bibtex.txt`：完整 BibTeX 条目
- `sections/`：abstract.md、Introduction.md、Related Work.md 等摘要
- 全部真实可核验（F04 会查）

### 继续前的 sanity check
- 外行能一句话听懂吗？
- 有明确实验能测试想法吗？
- 资源（数据/算力/时间）够吗？
- 贡献对一篇论文够大吗？
- 所有引用都是真实可核验的出版物吗？

## 通用原则

### 来自 Schulman
- 选对问题的能力比技巧本身更重要
- 观察哪些想法繁荣、哪些被遗忘——这培养品味
- Goal-driven 研究被抢先的风险低于 Idea-driven
- 做别人或文献提出的想法不丢人

### 来自 Si et al.（LLM 选题研究）
- AI 生成的想法通常新颖但缺乏可行性——锚定实际约束
- 模糊的实现细节是第一大弱点——具体说明方法如何工作
- 缺 baseline 和不现实假设是常见失败
- 对照已有工作验证——80% 的拒稿都引用了作者漏掉的已有论文

### 来自 ResearchAgent（Baek et al.）
- 跨论文联系想法，不只在一篇论文内
- 跨子领域找共享概念
- 迭代细化提升想法质量——2-3 轮后收益递减
