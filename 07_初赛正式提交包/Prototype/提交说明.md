# 初赛提交说明

## 1. 提交内容

本目录包含正式提交所需的源码、文档、实验材料、英文论文和 Agentic Reviewer Token。

- `paper/paper.pdf`：15 页英文 PDF；
- `AgenticReviewer/paperReview-AccessToken.txt`：与论文对应的 Access Token。该文件仅用于正式交付，校验器只检查其存在与非空，不读取、不输出、不写入 Git。

## 2. 官方目录映射

| 官方要求 | 本包位置 |
|---|---|
| 英文论文 PDF | `paper/paper.pdf` |
| Agentic Reviewer Token | `AgenticReviewer/paperReview-AccessToken.txt` |
| Agent 源码 | `code/` |
| 架构设计 | `docs/architecture.md` |
| openJiuwen 模块调用 | `docs/module_call.md` |
| 创新点 | `docs/innovation.md` |
| 框架贡献 | `framework_contribution.md` |
| 资源报告 | `resource_report.md` |

额外的实验和 Harness 证据位于 `evidence/`、`harness_packages/`。

## 3. 提交前校验

```powershell
python verify_submission.py --stage final
```

预期：`valid=true`。final 校验使用 `pypdf` 检查 PDF 可读性和页数是否与 manifest 一致；脚本不连接评审服务。

## 4. 代码环境

- JiuwenSwarm 使用 Python >=3.11,<3.14（推荐 3.11 或 3.12）；独立 UCR 核心可用 Python 3.10+；
- 测试使用 pytest 8+；
- final PDF 校验需要 `pypdf`（可执行 `python -m pip install -r requirements-verification.txt`）；
- JiuwenSwarm 依赖见 `code/03_技术实现/jiuwenswarm/pyproject.toml` 和 `uv.lock`；
- 前端依赖见对应 `package.json` 和锁文件；
- 不提交 `.venv` 或 `node_modules`。

## 5. 实验复现

JIT 离线验证：

```powershell
cd code/03_技术实现/ucr_benchmark
python verify_jit_comparison.py ../../../evidence/jit_comparison_v2_final
```

授权研究完整证据位于 `evidence/research_matrix_authorized/`。JIT v2 可按上述命令独立验证。
真实 Provider 重跑需要明确授权和环境变量 Key。

## 6. 结论边界

- UCR 是过程证据指标，不是领域准确率；
- JIT v2 是确定性 fixture，不产生模型费用；
- seed 43/44 的新增来源未获正式引用批准；
- 只有授权运行中的允许来源和 Claim 可以进入论文。

## 7. 提交前检查

1. 确认 `paper/paper.pdf` 与 `submission_manifest.json` 的页数和 SHA-256 一致。
2. 确认 Token 文件名为 `paperReview-AccessToken.txt`。
3. 重新生成 `CHECKSUMS.sha256`（Token 为安全例外，不写入清单）。
4. 运行 final 校验后压缩 `Prototype/` 为 `Prototype.zip`。
